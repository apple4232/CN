이론 연결 - **2-1 · 2-2차시 전체** (§2.1 ~ §2.2) · 1주차 1-3차시 코딩 에이전트

제출 위치 - `w02-agent/out/`

## 준비

1주차 1-3차시에서 설치한 코딩 에이전트를 씁니다. Codex 든 Claude Code 든 상관없습니다.
프로젝트의 **Source folder 를 이 폴더로** 지정하세요. 다른 폴더는 보이지 않게 두는 편이 좋습니다.

## 태스크 1 · 근거 자료 수집 (기본)

에이전트에게 시킬 것입니다. **직접 받지 마세요.**

```
> materials 폴더를 만들고, 거기에 HTTP 와 QUIC 의 근거 문서를 모아 줘
> - HTTP/1.1, HTTP/2, HTTP/3, QUIC 의 RFC 원문
> - QUIC 을 왜 만들었는지 다루는 논문이나 설계 문서 2 ~ 3편
> - 파일명은  rfc<번호>_<짧은 제목>  과  저자_연도_제목  형식으로
> - 목록을 out/source-list.md 에 정리
```

그다음 **분석을 시킵니다.**

```
> materials 폴더의 문서를 모두 읽고 out/analysis.md 로 정리해 줘
> - 문서마다  RFC 번호 · 연도 · 해결한 문제 · 핵심 메커니즘 · 포기한 것  을 표로
> - 표 아래에 HTTP/1.1 에서 HTTP/3 까지 문제가 어떻게 옮겨 갔는지
> - 원문에서 확인하지 못한 항목은 (확인 필요) 로 표시
> - 실제로 열어 보지 않은 RFC 번호는 쓰지 말 것
```

> **여기서 확인할 것** - 파일 몇 개를 직접 열어 보세요.
> `rfc9114` 라는 이름의 파일 안에 다른 것이 들어 있어도 에이전트는 모릅니다.

## 태스크 2 · 조사 심화와 이중 검증

### 2-1 기록 시트

```
> materials 에 TLS 1.3, 그리고 HTTP 의미론과 캐싱 RFC 를 추가하고
> 모든 문서를 out/record.md 로 기록해 줘
> - 열 :  번호 · 제목 · 연도 · 상태 · 폐기한 문서 · 폐기됨 여부 · 이 조사에서의 의미
> - 확인하지 못한 항목은 빈칸 대신 (확인 필요) 로
```

**폐기 열이 왜 필요한가** - 폐기된 RFC 도 여전히 내려받히고 권위 있어 보입니다.
이 열이 없으면 언젠가 죽은 규격을 인용하게 됩니다.

### 2-2 설정으로 내리기

두 번 말한 지시는 프롬프트가 아니라 설정에 있어야 합니다.

```
> 내가 반복해서 지시한 것을 보고 AGENTS.md 에 규칙으로 넣어 줘
>   (저장 위치 · 시트 열 · 열어 보지 않은 규격은 인용하지 않기 ·
>    RFC 가 폐기됐는지 항상 기록하기)
> 무엇을 왜 바꿨는지 요약해 줘
```

### 2-3 보고서

```
> materials 와 record 를 근거로 out/report.md 에 초안을 써 줘
> - 버전마다 :  해결한 문제 · 포기한 것 · 아직 남아 있는 것
> - 마지막에 선두 차단이 단계마다 어디로 옮겨 갔는지
> - 프로토콜 주장에는 RFC 번호와 절을 붙일 것
> - 원문에서 확인한 것만 쓸 것
```

### 2-4 이중 검증 · **이 실습의 핵심**

```
> 읽기 전용 reviewer 에이전트를 만들어 record 와 report.md 를 검사하고
> 결과를 out/review.md 로 써 줘
> - (1) 읽어서 - 인용한 주장을 원문과 하나씩 대조
> - (2) 코드로 - RFC 번호 · 제목 · 상태를 IETF datatracker 와 스크립트로 대조
> - 두 결과가 다른 항목은 표로 모을 것
> - 검증 못 한 인용은 삭제하지 말고 남겨 둘 것
```

읽는 검증과 코드 검증은 **실패하는 방식이 다릅니다.**
읽기는 왜곡된 의미를 잡고, 코드는 존재하지 않는 번호를 잡습니다.
그래서 둘이 일치하면 의미가 있고, **어긋나는 지점이 가장 흥미롭습니다.**

## observation.md 에 쓸 것

- 에이전트가 **지어낸 RFC 번호**가 있었는가. 어느 검증이 그것을 잡았는가
- 두 검증이 어긋난 항목이 있었다면 **여러분은 어느 쪽을 믿었고 왜인가**
- 프롬프트를 구체적으로 쓴 것과 두루뭉술하게 쓴 것의 결과 차이
